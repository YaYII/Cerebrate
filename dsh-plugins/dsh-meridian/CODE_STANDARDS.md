# dsh-meridian 代码规范（项目宪法）

> 强制性工程规范，不满足即 P0 缺陷。

## 1. 注释语言（强制）
全部简体中文；英文散文注释 = P0 缺陷（专有名词与 JSDoc 标签行除外）。

## 2. 注释规范（强制）
文件头说明「本文件干什么、不干什么」；公开函数 JSDoc 写明用途/参数/返回；注释解释「为什么」。

## 3. 架构模式（强制）
- features/ 是砖块：原子、可复用、不含任何项目专属词汇，禁止 import packs/ 与 business/。
- packs/ 是数据：只声明「某个被观测系统长什么样」（日志格式 + 消息规则），零逻辑。
- business/ 是组合：只做编排，可自由重组。
- index.ts 只做注册。

## 4. 产品铁律（本项目特有，强制）
1. **格式即声明**：禁止把日志格式硬编码进解析代码。
2. **覆盖度必披露**：任何解析结果必须同时给出「看到了多少 / 漏了多少 / 样本」。
3. **失败必显式**：解析失效时 verdict 必须为 failed，禁止把空结果当作「系统无问题」。
4. **事实必带证据**：每条事实必须能凭 `evidence.line` 回跳原始日志。
5. **事件 ID 与文案解耦**：只用来源 + 行号生成，保证改文案不破坏基线。

## 5. 类型与风格（强制）
禁 `any` / `@ts-ignore`；遵守 `exactOptionalPropertyTypes`；2 空格缩进、单引号、无分号、行 ≤ 120、具名导出。

## 6. 完成门禁（强制）
```bash
node scripts/check-all.mjs   # 注释语言 → tsc → 单元测试，全过才算完成
```

## 7. 证据文化（强制）
- 任何「竞品/原实现有缺陷」的结论必须附可复现实验（本项目已有：原解析器 0/144 命中的反证测试）。
- 语料必须来自真实运行产物，禁止用想象的数据写断言。
