# dsh-program-cognition 代码规范（项目宪法）

> 强制性工程规范，不满足即 P0 缺陷。以「能否作为教材范例」为验收标准。

## 1. 注释语言（强制）
- 全部简体中文；英文注释 = P0 缺陷；专有名词（API/DSH/Cordis 等）例外。

## 2. 注释规范（强制）
- 文件头注释说明「本文件干什么、不干什么」。
- 公开函数 JSDoc：一句话用途 + 关键参数 + 返回值。
- 注释解释「为什么」，不解释「是什么」。禁死代码/TODO 遗留。

## 3. 架构模式（强制）
- 功能是砖块：features/ 原子、可复用、不随业务改变、只增不减。
- 业务是组合：business/ 只做编排组合，自由重组。
- 功能层禁止 import 业务层；功能层禁止业务专属词汇（依赖单向）。
- 引擎 B 装配只允许 index.ts 注册事件监听；features/agentTrace 只做纯聚合。

## 4. 命名规范（强制）
- 文件小驼峰；函数/变量小驼峰；常量全大写下划线；类型/接口大驼峰。
- 名称必须表意。

## 5. 类型安全（强制）
- 禁 any / @ts-ignore；边界输入显式校验；遵守 exactOptionalPropertyTypes
  （可选字段用条件展开 `...x === undefined ? {} : { x }`）。

## 6. 代码风格（强制）
- 2 空格缩进；单引号；无分号；行 ≤ 120 字符；具名导出。

## 7. 安全红线（强制）
- 任何写入被观测项目源码的路径：dryRun 默认 + 备份可回滚。
- 任何行为记录/摘要：必须过 redact.ts 脱敏（黑名单 + 截断）。

## 8. 提交规范（强制）
- `类型(模块): 中文描述`；一个提交只做一件事。

## 9. 完成门禁（强制，每次代码修改后立即执行）
```bash
node scripts/check-all.mjs   # 注释语言 → tsc → vitest → tsdown，全过才算完成
```

## 10. 观测文化（强制）
- 业务流转靠实测证据（cog_trace），AI 行为靠记录（cog_agent），不靠猜。
