## 🚀 核心技术亮点

| 创新点 | 实现方式 | 价值 |
|--------|----------|------|
| **单一数据源契约** | contracts.ts 单一注册表 → index/render/features 三方共用 | 0 重复描述、0 漂移 |
| **ToolFactory** | 5 个 defineTool 合为 1 个 buildTool(contract, impl) | 注册代码 80% 减少 |
| **PageFactory (buildPage)** | 统一 frontmatter/TOC/TL;DR/页脚组装 | 7 个页面函数消除重复组装逻辑 |
| **FeatureBlock/FeatureList** | 契约 → 功能清单页自动渲染 | 文档与代码 100% 同源 |
| **DiagramFactory** | 4 种 Mermaid 统一入口 | 图表生成逻辑复用 |
| **源码 digest 进化** | gitHead + 源码 sha256 聚合 | 非 git 仓库也能精准判变 |
| **孤儿清理** | writeWikiPages 内建 expected Set 对比 | 零残留文件 |
| **递归索引页** | 递归扫描 00-README.md | 任意深度目录结构 |
| **双阅读架构** | Human (TOC/导览/编号) / AI (frontmatter/token_estimate/F编号) | 同一份内容双模式 |

## 🏆 核心价值主张

> **一句话：代码即语言，知识库是它对人和 AI 的双向翻译。**

| 维度 | 传统文档 | dsh-project-wiki |
|--------|----------|------------------|
| 内容来源 | 人工撰写 | 代码自动提取（1:1 同步） |
| 更新机制 | 手动/定期 | 代码变更→digest 变化→自动进化 |
| 人类阅读 | 靠经验找 | TOC + F编号 + 导读表 + TL;DR |
| AI 阅读 | 全量喂模型 | frontmatter + F编号 + 摘要 + 索引层 |
| 维护成本 | 高（易过期） | 零人工（代码即文档） |
| AI 协作 | 吃全文 | 索引层→详情层渐进披露 |
