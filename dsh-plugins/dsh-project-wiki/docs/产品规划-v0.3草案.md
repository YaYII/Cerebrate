# dsh-project-wiki 产品规划：从插件到双阅读知识库引擎

> 版本: v0.3 规划稿 | 日期: 2026-08-24 | 数据: GitHub 实测 + 双阅读调研(待融合)

## 0. 愿景

让任何代码仓库自动成为"人类可读 + AI 可读"的双阅读知识库，代码一变文档即变。
> 一句话：代码是语言，知识库是它的翻译——对着两个读者（人、AI）同时翻译。

## 1. 现状盘点（v0.1 已具备）

- 5 个工具闭环：scan/generate/evolve/diagram/status
- 8 页知识库：宏观到微观金字塔 + 功能清单 + 指南 + 概念
- 工厂模式 + 契约注册表（单一数据源，无重复）
- digest 进化（gitHead + 内容哈希双信号）
- 每页 TOC + F-编号 + 阅读导览 + 孤儿清理
- 零依赖、MIT、纯本地

## 2. 产品差距（插件到产品）

| 维度 | 现状(插件) | 目标(产品) |
| --- | --- | --- |
| 单项目 | 一次一个项目 | 多项目索引 + 切换 |
| 人类阅读 | 每页TOC/编号 | 项目索引页/侧边栏/面包屑 |
| AI阅读 | frontmatter/表格 | 机器索引JSON + AI摘要 + RAG友好 |
| 发布 | 仅Obsidian | 免费静态站(Quartz路线)/企业内网 |
| 自动化 | 手动evolve | git hook / CI 自动进化 |
| 规模 | 单机 | 大仓库增量扫描 |
| 协作 | 单人 | 团队多项目/权限 |
| 商业模式 | 无 | 开源核心 + 企业版 |

## 3. 产品路线图

### v0.2（可读性增强，2-3天）
- 项目索引页（列出所有项目+页数+更新时间）
- 每页 frontmatter 增加 summary 字段（AI 摘要）
- 机器可读索引 .wiki-index.json（AI 导航）
- git hook 示例（post-commit 自动 evolve）

### v0.3（规模与发布，1-2周）
- 大仓库增量扫描（git diff 文件级）
- 发布：Quartz 兼容输出 / 静态站导出
- CLI 一体化（dsh-wiki generate --all）
- 多语言 AST 升级（Go/Rust 声明提取）

### v1.0（产品化）
- 企业版：私有部署/权限/CI/审计
- 多项目工作区 + 全局搜索
- 语义索引（向量化 → RAG 检索）

## 4. 商业模式（价值上亿的路径）

- 开源核心：MIT 免费扩大采用（对标 Docusaurus 66k star）
- 企业版收费点：
  1. 私有化部署（合规团队）
  2. CI/CD 集成（GitHub Action 自动文档）
  3. 多项目治理（索引/权限/审计）
  4. 高级检索（语义搜索）
- 生态位：文档"生成层"（上游）→ 对接现有站点/知识库
