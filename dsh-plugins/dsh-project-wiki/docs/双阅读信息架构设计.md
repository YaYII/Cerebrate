# 双阅读信息架构（Human-readable × AI-readable）

设计原则：同一份知识库，人类通过视觉导航+渐进披露阅读，AI 通过结构化检索+分层拉取阅读。两者共用信息骨架，暴露不同入口。

## 一、人类阅读路径（视觉 + 导航）

00-总览(门面:TOC+导读+功能卡片)
  -> 01-架构(图) 图表优先看到整体
  -> 02-模块 渐进下钻
  -> 03-时序/流程 理解运行过程
  -> 04-API 微观查找
  -> 05-功能清单 产品视角(F-编号)
  -> 06-指南 任务驱动
  -> 07-概念 为什么

人类导航机制（对齐开源共识）:
- 每页 TOC（Quartz toc: maxDepth/minEntries）
- 数字前缀 00-07（VitePress/Docusaurus 惯例）
- 双链[[链接]]（Obsidian 原生）
- 待办: 项目索引页（Docusaurus autogenerated）、页内回到顶部

## 二、AI 阅读路径（结构化 + 分层拉取）

第1步: wiki_status/scan 得到项目骨架(JSON)
第2步: 读 00(总览: TOC/编号) 决定去哪页
第3步: 按需拉取 04(签名字段)/05(契约表)
第4步: evolve 双信号判断新鲜度(不读过期文档)

AI 导航机制（LLM 上下文工程）:
- frontmatter 结构化元数据(project/git_head/tags/created/updated)
- 表格化契约(token 高效, LLM 友好)
- F-编号稳定引用(AI 对话可引用 F-02 入参)
- Mermaid 源码内嵌(LLM 直接读 DSL)
- 待办: 每页 AI 摘要(summAry 字段)、机器可读索引 JSON

## 三、重叠与差异

| 机制 | 人类 | AI | 说明 |
| --- | --- | --- | --- |
| 目录TOC | 视觉锚点跳转 | 结构预览 | 共用 |
| F-编号 | 产品沟通 | 对话引用 | 共用 |
| 图表 | 渲染看图 | 读DSL源码 | 共用 |
| frontmatter | 不明显 | 元数据 | AI专用 |
| 表格 | 快速浏览 | 高密度 | 共用 |
| 双链 | 点击跳转 | 语义关联 | 人类优先 |
| 索引页 | 总览 | 导航清单 | 共用 |
